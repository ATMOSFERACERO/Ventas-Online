1 Cómo se conecta una app con un flujo

Todas las herramientas de flujos (n8n, Fluxion8n, Power Automate…) se conectan igual: la aplicación hace una petición HTTP a una dirección que el flujo tiene abierta, y el flujo contesta.

1.1 La idea en un minuto

Un flujo es una cadena de pasos (nodos) que alguien ha dibujado: «cuando llegue un mensaje, pregunta a la IA, guarda el resultado y devuélvelo». Para que otra aplicación pueda empezar ese flujo, el primer paso es un disparador (trigger) que escucha en una URL. Esa URL se llama webhook.

1. Tú configuras el flujo
Pones un disparador Webhook (o «When an HTTP request is received») y copias su URL.
2. La app llama a la URL
Envía una petición POST con un JSON: el mensaje, la sesión, el contexto.
3. El flujo trabaja
Ejecuta sus nodos: IA, bases de datos, correo…
4. El flujo responde
Devuelve un JSON con el resultado, que la app muestra al usuario.

1.3 Cómo leer este manual

Todo el código está en recuadros oscuros con un botón Copiar. El texto normal es texto; lo que va en recuadro oscuro es algo que se escribe o se pega tal cual. Los colores significan:

Nombres de campos y opcionesTextos entre comillasNúmerosComentarios (explican el código; no se escriben)Comandos
Nota sobre los comentarios

El JSON real no admite comentarios. En este manual algunos recuadros JSON llevan líneas que empiezan por // para explicarlos; el botón Copiar las quita automáticamente. Si copias a mano, bórralas.

Qué está comprobado y qué no

Corpus n8n = contrastado con la documentación oficial de n8n incluida en el repositorio (Documentos/Conocimiento/n8n/).
Sin verificar = escrito de memoria o a partir de búsquedas; no se pudo abrir la documentación oficial en directo. Compruébalo antes de depender de ello.

1.4 El contrato de mensajes

Para que dos programas se entiendan hay que acordar qué se envía y qué se recibe. Es el contrato. Este manual usa uno sencillo que funciona en todas las plataformas. Si tu flujo ya existe con otro formato, se adapta con un nodo intermedio.

json · petición (la app → el flujo)
{
  // Datos que la aplicación envía por POST con Content-Type: application/json
  "action": "sendMessage",            // compatible con el Chat Trigger de n8n (ver 2.7)
  "sessionId": "usuario-42-sesion-1", // identifica la conversación; el flujo puede usarlo como memoria
  "chatInput": "Busco una bici de montaña barata", // lo que escribió la persona
  "systemPrompt": "Eres el asistente de una tienda de segunda mano.", // instrucciones fijas para la IA (opcional)
  "test": false                       // true cuando es una prueba de conexión
}
json · respuesta (el flujo → la app)
{
  // Texto que la app mostrará. "output" es el nombre que usa el Chat Trigger de n8n.
  "output": "Te recomiendo la bicicleta de montaña de 120 €."
}
Consejo

Haz que el flujo responda siempre con la clave output. Una app tolerante puede aceptar también reply, text o message, pero es mejor no depender de ello.

1.5 Dónde se configura en Segundamano

En la aplicación, abre Ajustes. Hay dos pestañas y el mismo esquema de tarjetas para las dos:

PestañaPara qué sirveCampos
Cuentas de IAConectar directamente con un proveedor de modelos (Anthropic, OpenAI, Gemini o un servidor compatible).Nombre, proveedor, host, API Key, modelo.
Flujos (n8n y similares)Conectar con un webhook de n8n, Fluxion8n, Power Automate u otra herramienta (secciones 2 a 6 de este manual).Nombre, herramienta, URL, autenticación (ninguna, cabecera, Basic, Bearer), tiempo de espera.
  • Añadir: botón «+ Añadir…» → ventana con el formulario y Probar conexión antes de guardar.
  • Editar: el lápiz de cada tarjeta. Borrar: la papelera (con confirmación); se puede borrar cualquiera, también la activa.
  • Activa: solo una conexión a la vez. La primera que das de alta queda activa; las demás se activan con «Activar cuenta».
  • Respaldo automático: si la conexión activa es un flujo y falla (error, tiempo agotado o respuesta sin texto), la app pasa sola a la cuenta de IA que hayas elegido como respaldo y lo avisa en el chat. Si la activa es una cuenta de IA y falla, se muestra el error.
  • Sin conexiones: el botón «Asistente» queda bloqueado (gris) y explica por qué; también si hay conexiones pero ninguna activa.
Desde el navegador

Segundamano se ejecuta en el navegador, así que las llamadas a tu flujo están sujetas a las reglas del navegador: CORS (permite el origen en el flujo; abierta con doble clic, la web tiene origen «null», que solo acepta *), contenido mixto (una web https no puede llamar a una URL http) y redes privadas (localhost o 192.168.x.x pueden estar restringidas). Si Probar conexión falla con «CORS, una dirección privada o contenido mixto», es una de estas tres.

Claves en el navegador

En este prototipo las claves se guardan sin cifrar en el almacenamiento del navegador. Sirve para una demostración; para un uso real, las llamadas y las claves deben vivir en un servidor.

2 n8n Corpus n8n

n8n expone sus flujos al exterior con el nodo Webhook. Es la vía normal para que una aplicación lo llame.

2.1 Antes de empezar

  • Un n8n accesible desde donde corre tu aplicación (misma máquina, red local o Internet).
  • Un flujo publicado/activo: la URL de producción solo funciona con el flujo activo.
  • Decidir la autenticación (sección 2.4) antes de exponer la URL.

2.2 El nodo Webhook

Es un nodo disparador: «cuando llegue una petición a esta dirección, empieza el flujo». Sus ajustes principales:

AjusteQué haceValor recomendado para una app
HTTP MethodMétodo HTTP aceptado (GET, POST, PUT, PATCH, DELETE, HEAD).POST, porque llevamos un JSON en el cuerpo.
PathParte final de la URL. Por defecto es un texto aleatorio; puedes poner uno fijo.Uno claro y no adivinable, p. ej. asistente.
AuthenticationExige credenciales: Basic auth, Header auth, JWT auth o ninguna.Header auth (sección 2.4).
RespondCuándo y cómo se contesta: Immediately, When Last Node Finishes, Using 'Respond to Webhook' Node o Streaming response.Using 'Respond to Webhook' Node (control total de la respuesta).

Opciones útiles (Add Option): Allowed Origins (CORS), IP(s) Allowlist (solo esas IP pueden llamar; las demás reciben 403), Raw Body, Response Headers y Only Run If (solo ejecuta si una expresión sobre la petición es cierta).

Qué recibe el flujo

Dentro del flujo, la petición llega como { body, headers, params, query }. Tu JSON está en $json.body; por ejemplo, el texto del usuario es {{ $json.body.chatInput }}.

2.3 URL de prueba y URL de producción

El nodo muestra dos direcciones. Confundirlas es el error nº 1.

URL de pruebaURL de producción
Formahttps://TU-N8N/webhook-test/RUTAhttps://TU-N8N/webhook/RUTA
Cuándo funcionaSolo mientras pulsas Listen for test event (o Execute workflow); atiende una llamada.Siempre que el flujo esté publicado/activo.
¿Se ven los datos en el editor?Sí, al instante.No; se consultan en la pestaña Executions.
Úsala para…Construir y depurar.La configuración de tu aplicación.
Atención

Si pegas la URL de prueba en tu aplicación, funcionará una vez y después dará 404. En la aplicación se usa siempre la de producción.

2.4 Autenticación

Sin autenticación, cualquiera que conozca la URL puede ejecutar tu flujo (y gastar tus créditos de IA). Opciones del nodo Webhook:

MétodoCómo se configura en n8nQué envía la app
Header auth (recomendado)Credencial con un Name de cabecera y un Value secreto.Una cabecera con ese nombre y valor.
Basic authCredencial con usuario y contraseña.Authorization: Basic base64(usuario:clave)
JWT authCredencial JWT (clave compartida o PEM).Authorization: Bearer TOKEN_JWT firmado.
None—Nada. Solo para pruebas locales.

Ejemplo: Header auth

  1. En el nodo Webhook, Authentication → Header Auth → Create new credential.
  2. Name = X-Api-Key; Value = una clave larga y aleatoria (guárdala en tu gestor de contraseñas).
  3. En la aplicación, configura esa misma cabecera y valor.
bash · generar una clave aleatoria
# Genera 32 bytes aleatorios en hexadecimal: úsalos como valor de la cabecera
openssl rand -hex 32
bash · probar la llamada con curl
# -X POST        → método HTTP
# -H "..."       → cabeceras: tipo de contenido y la clave de autenticación
# -d '...'       → cuerpo JSON de la petición
curl -X POST "https://TU-N8N/webhook/asistente" \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: PEGA_AQUI_TU_CLAVE" \
  -d '{"action":"sendMessage","sessionId":"prueba-1","chatInput":"Hola","test":true}'

2.5 Devolver la respuesta

El ajuste Respond del Webhook decide qué recibe la app:

OpciónQué devuelve¿Sirve para un asistente?
ImmediatelyUn mensaje fijo («Workflow got started») sin esperar al flujo.No: la app no recibe la respuesta de la IA.
When Last Node FinishesLos datos del último nodo (todas las entradas, la primera en JSON o sin cuerpo, según Response Data).Sí, si el último nodo ya produce output.
Using 'Respond to Webhook' NodeLo que tú definas en un nodo Respond to Webhook (JSON, texto, entrada, redirección…).Sí, es la más flexible.
Streaming responseVa enviando texto según se genera (requiere nodos con soporte, como AI Agent).Solo si la app sabe leer streaming.
Comportamientos del nodo Respond to Webhook

Si el flujo termina sin ejecutarlo, devuelve un mensaje estándar con 200. Si falla antes de llegar a él, devuelve un error 500. Si se ejecuta un segundo nodo de respuesta, se ignora. Se ejecuta una sola vez con el primer elemento.

2.6 Ejemplo completo paso a paso

Un flujo mínimo que recibe el mensaje y devuelve un eco. Sirve para comprobar la conexión antes de añadir la IA.

  1. Crea un flujo nuevo y añade el nodo Webhook: método POST, ruta asistente, autenticación Header Auth, Respond = Using 'Respond to Webhook' Node.
  2. Añade Respond to Webhook detrás: Respond With = JSON.
  3. Escribe el cuerpo de la respuesta (código de abajo).
  4. Pulsa Listen for test event y prueba con la URL de prueba y curl.
  5. Publica el flujo y repite con la URL de producción.
js · cuerpo del nodo «Respond to Webhook» (expresión de n8n)
// Las expresiones de n8n van entre {{ }} y empiezan con "=" cuando son todo el campo.
// $json.body es el JSON que mandó la app; chatInput es el texto de la persona.
={{ { "output": "Recibido: " + $json.body.chatInput } }}

Para ahorrar tiempo, puedes importar este flujo (menú ⋯ → Import from file / URL, o pegarlo con Ctrl+V sobre el lienzo). Después selecciona tu credencial en el Webhook.

json · flujo importable (orientativo)
{
  "name": "Asistente - respuesta de prueba",
  "nodes": [
    {
      "parameters": {
        "httpMethod": "POST",
        "path": "asistente",
        "authentication": "headerAuth",
        "responseMode": "responseNode",
        "options": {}
      },
      "name": "Webhook",
      "type": "n8n-nodes-base.webhook",
      "typeVersion": 2,
      "position": [0, 0]
    },
    {
      "parameters": {
        "respondWith": "json",
        "responseBody": "={{ { \"output\": \"Recibido: \" + $json.body.chatInput } }}",
        "options": {}
      },
      "name": "Respond to Webhook",
      "type": "n8n-nodes-base.respondToWebhook",
      "typeVersion": 1.1,
      "position": [240, 0]
    }
  ],
  "connections": {
    "Webhook": { "main": [[ { "node": "Respond to Webhook", "type": "main", "index": 0 } ]] }
  }
}
Sin verificar

Los números de versión de los nodos (typeVersion) y los nombres internos de parámetros pueden variar entre versiones de n8n. Si la importación se queja, crea los dos nodos a mano con la tabla de la sección 2.2.

Añadir la IA

Sustituye el eco por un nodo AI Agent (o Basic LLM Chain) con su modelo y pon como entrada {{ $json.body.chatInput }}. Después, en Respond to Webhook, devuelve la salida del agente como output.

2.7 Variante: Chat Trigger

El nodo Chat Trigger es un disparador pensado para asistentes de chat: añade interfaz de chat alojada, memoria por sesión y se conecta directamente a un agente. Admite autenticación None, Basic Auth o n8n User Auth. El modo Embedded Chat te da una Chat URL a la que puede llamar tu propia interfaz.

Ojo con el consumo

Cada mensaje al Chat Trigger ejecuta el flujo: una conversación de 10 mensajes son 10 ejecuciones.

Sin verificar

El formato exacto del cuerpo que acepta la Chat URL (action, sessionId, chatInput) y que la respuesta venga en output es el que usa el widget oficial de n8n; está escrito de memoria. Por eso el contrato de la sección 1.4 usa esos mismos nombres.

2.8 Red, CORS y límites

  • Tamaño máximo: el cuerpo de un webhook admite hasta 16 MB (en n8n autoalojado se cambia con N8N_PAYLOAD_SIZE_MAX).
  • CORS: solo afecta a llamadas hechas desde un navegador. Ajusta Allowed Origins (CORS) en las opciones del Webhook con el dominio de tu app. Si la llamada la hace un servidor, CORS no interviene.
  • Lista de IP: la opción IP(s) Allowlist limita quién puede invocar el webhook (403 si no está en la lista).
  • HTTPS: en Internet, usa siempre HTTPS (la clave viaja en una cabecera).
  • Tiempo: una IA puede tardar decenas de segundos. Configura en la app un tiempo de espera generoso (p. ej. 120 s).

3 Fluxion8n

Fluxion8n es una réplica de n8n: el nodo Webhook, el nodo Respond to Webhook y la forma de autenticar funcionan como se explica en la sección 2.

3.1 Qué es igual que n8n

Disparador
Nodo Webhook con método, ruta y autenticación.
Respuesta
Nodo Respond to Webhook o «When Last Node Finishes».
Contrato
El mismo JSON de la sección 1.4 sirve sin cambios.
Modos de URL
Prueba (mientras escuchas) y producción (flujo activo).
Sin verificar

Este manual no analiza el código de Fluxion8n: asume que replica n8n. El formato exacto de la URL puede diferir; usa siempre la dirección que te muestra el propio nodo Webhook en Fluxion8n, no la de los ejemplos.

3.2 Pasos

  1. Abre el flujo en Fluxion8n y añade el nodo Webhook: POST, una ruta propia y autenticación por cabecera.
  2. Añade Respond to Webhook con el JSON { "output": "…" }.
  3. Activa el flujo y copia la URL de producción del nodo.
  4. Prueba con curl (sección 2.4) cambiando la URL por la tuya.
  5. En la aplicación que llamará al flujo, pega la URL y la cabecera.

3.3 Servidores en red local

Si Fluxion8n (o n8n) corre en tu ordenador o en un NAS, la URL será una dirección privada (localhost, 192.168.x.x…). Dos cosas pueden impedir la llamada:

  • Desde el navegador (como Segundamano): hace falta permitir el origen (CORS) en el flujo y no mezclar https con http. Ver sección 1.5.
  • Desde un servidor con protección SSRF: muchas aplicaciones bloquean por defecto las direcciones privadas. Hay que permitirlo expresamente en su configuración de administrador, nunca desde un flujo.
Alternativa

Publica el flujo detrás de un dominio con HTTPS (un proxy inverso o un túnel) y usa esa URL pública, con autenticación.

4 Power Automate Sin verificar

Power Automate (Microsoft) abre un flujo al exterior con el disparador «When an HTTP request is received» y contesta con la acción «Response».

Origen de esta sección

No se pudo abrir la documentación oficial de Microsoft desde el entorno donde se escribió este manual. Lo siguiente se basa en búsquedas y conocimiento general; verifica los nombres de menús y licencias en learn.microsoft.com. Además, este disparador es un conector premium (suele requerir licencia de pago).

4.1 El disparador HTTP

Al guardar el flujo, Power Automate genera una URL HTTP POST larga. Esa URL ya contiene una firma (parámetro sig=…): quien la conozca puede ejecutar el flujo. Es, a la vez, dirección y contraseña.

4.2 Quién puede llamar

Opción («Who can trigger the flow?»)SignificadoCuándo usarla
AnyoneCualquiera con la URL firmada (clave SAS en la URL).Pruebas y apps sencillas. Trata la URL como un secreto.
Any user in my tenantHace falta un token de Microsoft Entra ID de tu organización.Integraciones internas con identidad.
Specific users in my tenantSolo las cuentas/aplicaciones que enumeres.Más control.

4.3 Paso a paso (opción «Anyone»)

  1. En Power Automate: Crear → Flujo de nube instantáneo → disparador When an HTTP request is received.
  2. En Request Body JSON Schema pega un esquema como el de abajo (o usa Use sample payload to generate schema con el JSON de la sección 1.4).
  3. Añade tus acciones (p. ej. un conector de IA o Copilot Studio).
  4. Añade la acción Response: código 200, cabecera Content-Type: application/json y cuerpo con output.
  5. Guarda: el disparador mostrará la HTTP POST URL. Cópiala.
json · esquema del cuerpo de la petición
{
  // Describe qué campos espera el flujo. Con esto, Power Automate te ofrece
  // chatInput, sessionId… como "contenido dinámico" en las acciones siguientes.
  "type": "object",
  "properties": {
    "action":       { "type": "string" },
    "sessionId":    { "type": "string" },
    "chatInput":    { "type": "string" },  // texto de la persona
    "systemPrompt": { "type": "string" },
    "test":         { "type": "boolean" }
  }
}
json · cuerpo de la acción «Response»
{
  // Sustituye el texto por el contenido dinámico de tu acción de IA.
  "output": "Respuesta generada por el flujo"
}
bash · probar la llamada
# La URL completa (con ?api-version=...&sig=...) se pega ENTERA, entre comillas.
# No hace falta cabecera de autenticación: la firma ya va dentro de la URL.
curl -X POST "https://prod-00.westeurope.logic.azure.com:443/workflows/ID/triggers/manual/paths/invoke?api-version=2016-06-01&sig=FIRMA_SECRETA" \
  -H "Content-Type: application/json" \
  -d '{"action":"sendMessage","sessionId":"prueba-1","chatInput":"Hola","test":true}'
Tiempo de espera

Una llamada que espera una Response tiene un límite de tiempo (del orden de un par de minutos; sin verificar). Si tu IA tarda más, el llamante recibe un error aunque el flujo siga ejecutándose.

Si se filtra la URL

Regenera la clave del flujo (o crea el disparador de nuevo) para invalidar la URL antigua, y guarda la nueva en un lugar seguro. No la pegues en chats ni repositorios.

4.4 Variante con Microsoft Entra ID

Con Any user in my tenant o Specific users, la aplicación debe enviar un token de acceso de Microsoft Entra ID en la cabecera Authorization: Bearer …. Resumen del procedimiento:

  1. Registra una aplicación en Microsoft Entra ID y crea un secreto de cliente.
  2. Añade su identificador (o el de la cuenta) a la lista de usuarios permitidos del disparador.
  3. Pide un token con el flujo client credentials y úsalo en la llamada.
bash · obtener el token (esquema)
# Sustituye TENANT_ID, CLIENT_ID y CLIENT_SECRET por los de tu aplicación registrada.
# El valor de "scope" (recurso de Power Automate) está SIN VERIFICAR: confírmalo en la documentación de Microsoft.
curl -X POST "https://login.microsoftonline.com/TENANT_ID/oauth2/v2.0/token" \
  -d "grant_type=client_credentials" \
  -d "client_id=CLIENT_ID" \
  -d "client_secret=CLIENT_SECRET" \
  -d "scope=https://service.flow.microsoft.com//.default"
Sin verificar

El detalle del scope (con doble barra) viene de blogs de terceros, no de la documentación oficial. Esta variante es más compleja; si no la necesitas, usa «Anyone» con la URL como secreto.

5 Copilot Studio Sin verificar

Copilot Studio (Microsoft) crea agentes conversacionales. A diferencia de n8n, el agente no tiene «un webhook» por defecto: se llega a él por un canal o a través de un flujo.

5.1 Dos rutas posibles

Ruta A · mediante un flujo
Una app llama a un flujo de Power Automate (sección 4); ese flujo conversa con el agente o hace el trabajo. Es lo más parecido a n8n.
Ruta B · canal Direct Line
Tu app habla directamente con el agente publicado: obtiene un token, abre una conversación y envía/lee actividades.
Origen de esta sección

La ruta B (token, conversación, actividades) está contrastada con resultados de búsqueda sobre la documentación de Microsoft («Publish an agent to mobile or custom apps»); no se pudo abrir la página oficial. Los nombres de los menús de Copilot Studio cambian con frecuencia.

5.2 Ruta A: mediante un flujo de Power Automate

  1. Crea el flujo con When an HTTP request is received (sección 4).
  2. Dentro, usa las acciones que necesites: p. ej. enviar el texto a un conector de IA o llamar a otro servicio.
  3. Termina con Response y la clave output.
  4. Si quieres que el agente de Copilot Studio use ese flujo como herramienta, añádelo como acción/herramienta del agente desde Copilot Studio (la dirección contraria: agente → flujo).
Dos sentidos distintos

App → flujo usa el disparador HTTP (sección 4). Agente → flujo usa las herramientas del agente. No son lo mismo; elige según quién empieza la conversación.

5.3 Ruta B: canal Direct Line

Pasos para hablar con el agente publicado desde tu propio programa:

  1. En Copilot Studio, publica el agente y abre Canales → Aplicación móvil (u otro canal personalizado). Copia el Token Endpoint.
  2. Tu servidor (no el navegador) pide un token a esa dirección.
  3. Con el token, abre una conversación en Direct Line.
  4. Envía el mensaje del usuario como una actividad de tipo message.
  5. Lee las actividades nuevas (con watermark) hasta que llegue la respuesta del agente.
bash · Direct Line v3 paso a paso
# 1) Pedir un token al "Token Endpoint" copiado de Copilot Studio.
#    Devuelve algo como: { "token": "...", "expires_in": 1800, "conversationId": "..." }
curl "URL_DEL_TOKEN_ENDPOINT"

# 2) Abrir una conversación con ese token (en el endpoint global de Direct Line).
#    Devuelve { "conversationId": "...", "token": "...", ... }
curl -X POST "https://directline.botframework.com/v3/directline/conversations" \
  -H "Authorization: Bearer TOKEN"

# 3) Enviar el mensaje de la persona como una actividad de tipo "message".
curl -X POST "https://directline.botframework.com/v3/directline/conversations/CONVERSATION_ID/activities" \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"type":"message","from":{"id":"usuario-42"},"text":"Hola"}'

# 4) Leer las actividades nuevas. "watermark" evita releer las anteriores.
#    Busca las que tengan from.id distinto del tuyo: son del agente.
curl "https://directline.botframework.com/v3/directline/conversations/CONVERSATION_ID/activities?watermark=0" \
  -H "Authorization: Bearer TOKEN"
Seguridad

El secreto de Direct Line y el token no deben ir en código que se ejecute en un navegador. Pídelos desde el servidor y entrega al navegador, como máximo, el token de corta vida.

Diferencia de fondo con n8n

Direct Line es asíncrono: envías la actividad y luego consultas la respuesta. Un webhook de n8n devuelve la respuesta en la misma llamada. Si tu aplicación espera el formato de la sección 1.4, necesita un pequeño intermediario (un flujo o un servicio) que oculte ese ir y venir.

7 Seguridad

Un webhook es una puerta de entrada a tu automatización. Ciérrala con llave.

Autentica siempre
Cabecera secreta, Basic o JWT. «None» solo en local y para probar.
HTTPS
Sin cifrado, la clave viaja a la vista de cualquiera en la ruta.
Secretos fuera del código
Ni en repositorios, ni en capturas, ni en chats. Si se filtra: regenerar.
Lista de IP
Si la app tiene IP fija, limita quién puede llamar (IP(s) Allowlist en n8n).
Mínimo dato
Envía al flujo solo lo necesario; evita contraseñas y datos personales innecesarios.
Límites
Tiempo de espera, tamaño máximo y control de frecuencia para no agotar créditos de IA.
Redes privadas y SSRF

Una aplicación que llama a URLs que le da un usuario podría usarse para atacar tu red interna (SSRF). Por eso muchas aplicaciones bloquean las direcciones privadas por defecto; actívalo solo si eres administrador y lo necesitas.

8.2 Pasos mínimos

  1. Crea el disparador (Webhook / HTTP request) y publica el flujo.
  2. Copia la URL de producción y configura la autenticación.

8.4 Ejemplo en código (Node.js 18+)

js · llamada desde un servidor
// Función reutilizable: manda un mensaje a un flujo y devuelve el texto de la respuesta.
async function preguntarAlFlujo(url, clave, texto, sessionId) {
  // AbortSignal.timeout corta la espera si el flujo tarda demasiado (120 s aquí).
  const respuesta = await fetch(url, {
    method: "POST",
    headers: { "Content-Type": "application/json", "X-Api-Key": clave },
    body: JSON.stringify({ action: "sendMessage", sessionId, chatInput: texto }),
    signal: AbortSignal.timeout(120_000),
  });
  // Cualquier código que no sea 2xx es un fallo del flujo o de la autenticación.
  if (!respuesta.ok) throw new Error("El flujo respondió " + respuesta.status);
  const datos = await respuesta.json();
  // n8n con "All Entries" devuelve una lista; con Respond to Webhook, un objeto.
  const primero = Array.isArray(datos) ? datos[0] : datos;
  return primero.output ?? primero.reply ?? primero.text ?? "";
}

// Uso (la clave se lee del entorno, nunca se escribe en el código):
const texto = await preguntarAlFlujo(process.env.FLUJO_URL, process.env.FLUJO_CLAVE, "Hola", "s1");
console.log(texto);

9 Solución de problemas

SíntomaCausa probableQué hacer
404 Not FoundURL de prueba usada en producción, flujo sin publicar o ruta mal escrita.Usa la URL de producción y activa el flujo.
401 / 403Cabecera ausente o con valor incorrecto; IP fuera de la lista.Revisa nombre y valor de la cabecera; revisa la lista de IP.
405 Method Not AllowedEl Webhook espera otro método (p. ej. GET).Haz coincidir el método con el del nodo (POST).
500El flujo falló antes de responder.Mira la pestaña Executions y el nodo con error.
200 pero «Workflow got started» / mensaje genéricoRespond en «Immediately», o el flujo terminó sin pasar por Respond to Webhook.Cambia a «Using Respond to Webhook» y comprueba que ese nodo se ejecuta en todas las ramas.
Respuesta vacía o sin outputEl último nodo no produce esa clave.Construye la respuesta explícitamente (sección 2.6).
Tarda y falla por tiempoLa IA es lenta o el límite de espera es corto.Sube el tiempo de espera; en Power Automate, simplifica el flujo.
Error de red / «dirección no permitida»URL privada bloqueada (SSRF, navegador o contenido mixto).Usa una URL pública con HTTPS, o revisa las secciones 1.5 y 3.3.
Error CORS en el navegadorEl origen de tu web no está permitido.Ajusta Allowed Origins (CORS), o llama desde un servidor.
Funcionó una vez y dejó de funcionarEra la URL de prueba.Cambia a la de producción.
Método de diagnóstico

1) Prueba con curl fuera de tu aplicación. 2) Si curl funciona, el problema está en la configuración de la app. 3) Si no, está en el flujo o en la red.

10 Glosario de definiciones

Agente (de IA)
Programa que, además de responder, decide qué herramientas usar para cumplir una tarea.
API
Forma que ofrece un programa para que otros programas le pidan cosas.
Autenticación
Demostrar quién eres antes de que te dejen entrar (clave, usuario y contraseña, token).
Basic auth
Autenticación con usuario y contraseña codificados en una cabecera Authorization: Basic ….
Bearer (portador)
Cabecera Authorization: Bearer TOKEN: quien lleva el token tiene acceso.
Cabecera (header)
Dato extra que acompaña a una petición HTTP (tipo de contenido, clave…).
Canal
Vía por la que se habla con un agente (web, móvil, Direct Line…).
Contrato
Acuerdo sobre qué JSON se envía y qué JSON se recibe.
CORS
Regla del navegador que decide si una web puede llamar a otro dominio.
curl
Programa de línea de comandos para hacer peticiones HTTP; ideal para probar.
Direct Line
API de Microsoft para conversar con un agente desde tu propio programa.
Disparador (trigger)
Primer nodo de un flujo: lo que lo pone en marcha (un webhook, un horario…).
Endpoint
Dirección concreta a la que se hace una petición.
Entra ID
Servicio de identidad de Microsoft (antes Azure Active Directory).
Flujo (workflow)
Cadena de pasos automatizados.
Header auth
Autenticación mediante una cabecera personalizada con un valor secreto.
HTTP / HTTPS
Protocolo de la web; HTTPS añade cifrado.
JSON
Formato de texto para intercambiar datos: { "clave": "valor" }.
JWT
Token firmado que contiene datos y caduca; sirve para autenticar.
Nodo
Un paso del flujo (disparador, IA, correo, respuesta…).
Payload
El contenido útil de una petición o respuesta (el JSON).
Path (ruta)
Parte final de la URL que identifica un webhook concreto.
Petición / respuesta
Mensaje que envía quien llama / mensaje que devuelve quien contesta.
SAS (firma)
Clave incrustada en una URL que da acceso a quien la tenga (Power Automate: sig=).
sessionId
Identificador de una conversación para que el flujo sepa de cuál se trata.
SSRF
Ataque que engaña a un servidor para que llame a recursos internos que no debería.
Streaming
Respuesta que llega por trozos mientras se genera.
Timeout (tiempo de espera)
Máximo que se espera una respuesta antes de dar la llamada por fallida.
Token
Cadena temporal que sustituye a una contraseña para una sesión.
URL de prueba / de producción
Direcciones del webhook para construir/depurar y para uso real, respectivamente.
Webhook
Dirección que escucha peticiones de otras aplicaciones y pone en marcha un flujo.
